# 能力分级（A 模式 / A + B 模式）

> 本文与 `protocol/java/.../Capabilities.java` 的矩阵**由自检保证一致**：
> 文档漏写某个能力，`protocol/selftest.ps1` 会直接报错。改能力时两边一起改。

## 一句话

| 你填了什么 | 得到什么 |
|---|---|
| 只填 **地址** | A 模式：WebView 承载官方 UI + 诊断 + 多实例 |
| 地址 + **启动地址**（带 `?token=`） | A + B 模式：上面全部 **+ 原生会话、实时事件、发消息** |

## 矩阵

| 模式 | 能力 | 可用 |
|---|---|---|
| A 模式 | WebView 承载官方 UI | 是 |
| A 模式 | 多实例管理 | 是 |
| A 模式 | 401/502/530 诊断与连接预检 | 是 |

| A + B 模式 | 历史回填 + 实时事件 | 否 → 是 |

| A + B 模式 | 工具调用卡片 | 否 → 是 |

## 为什么 B 模式要额外一个地址

DSH 不在磁盘上保存可用的凭证：launch token **每次启动随机生成**，只打印在
`dsh web` 的 stdout 里。所以第三方客户端没法自动发现它，只能由用户粘贴一次。

`/connect?token=<launchToken>` 会换到一个签名 API Cookie，之后：

- **unary 调用**（列表/投影/发消息）走 `POST /api/<namespace/method>`
- **实时事件**走 WebSocket `/api/remote.mux`（`session/observeEvent`）

细节见 [protocol.md](protocol.md)。

## 降级行为

- 没有 API 凭证 → 原生入口**不显示**（不是显示了再报错）
- 有凭证但换取失败（token 过期/服务端拒绝）→ 原生页显示可读原因，并保留"官方界面"出口
- 实时连接断开 → 只显示"实时未连接"，历史仍然可看

## 已知不确定项

`assistant/message`（**模型成功回复**）的事件形状还没有实测证据 ——
隔离实例没有模型凭据，只能拿到失败路径（`assistant/attempt` + `turn/end` 的错误）。
所以原生聊天对"模型输出"的渲染目前是**按 message 形状的兜底实现**，
其余部分（用户消息、错误、工具卡片、实时追加）都已实测。
