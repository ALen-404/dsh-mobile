# 真机验收清单

> 构建机没有 adb/模拟器，所以这个项目的**所有界面都没在真机上跑过**。
> 这份清单是拿到 APK 后照着点的顺序，每步都写了「预期现象」和「不符合时怎么查」。
>
> 目标不是"证明它完美"，而是**尽快暴露真机问题**。

## 0. 准备

```powershell
# 1) 构建（或直接用别人给的 dist/dsh-mobile-debug.apk）
powershell -ExecutionPolicy Bypass -File build.ps1

# 2) 装到手机（两种都行）
adb install -r dist/dsh-mobile-debug.apk
# 或：把 APK 拷到手机，用文件管理器点开安装（需允许「安装未知来源应用」）
```

需要的环境：
- 手机能访问你的 DSH（同一 WiFi，或已通过隧道暴露成域名）
- 想测原生能力的话，还要一个**带 token 的启动地址**（见 §3）

## 1. 首启动（空状态）

| 步骤 | 预期 |
|---|---|
| 打开 App | 标题「DSH 实例」+ 右上角「帮助」；正文是**添加指引**，不是一片空白 |
| 点「帮助」 | 五个小节可滚动；能说清两种模式和 token 从哪来 |

❌ 不符合：截图发我（布局/文案问题）。

## 2. A 模式（只填地址）

| 步骤 | 预期 |
|---|---|
| 「＋ 添加实例」→ 名字随便、地址填 `http://<你的DSH>:3080` → 保存 | 列表出现一行，第二行显示地址 + `A 模式` |
| 点这一行 →「打开」 | 全屏官方 UI；顶栏有 `‹`、实例名、`⟳`、`⋯`，下方有细进度条 |
| 等页面加载 | 进度条走完后消失；页面正常显示（可能是登录/配对页） |
| 转屏（横→竖） | **不重建**：页面状态、滚动位置保留 |
| 点侧栏按钮 | 侧栏能展开；点会话能切换（这正是当初立项的痛点） |
| 按返回键 | 先回退网页历史，到顶再退出 App |

❌ 常见问题：白屏（看是否 401）、点侧栏没反应（竖屏适配层）、键盘遮挡输入框。

## 3. B 模式（原生能力，需要 token）

**拿 token**（在跑 DSH 的那台机器上）：

```powershell
# 用命令行启动，终端会打印一行带 token 的地址
dsh web --no-open --host 0.0.0.0 --port 3080
# 输出示例：dsh web: http://127.0.0.1:3080/?token=xxxxxxxx
```

> 桌面版 DSH（Electron）默认**不显示**这个地址。没有命令行环境时，B 模式就用不了 ——
> 这是 DSH 的设计（token 每进程随机、不落盘），不是 App 的缺陷。

| 步骤 | 预期 |
|---|---|
| 长按实例 →「编辑」→ 第三个输入框（提示语是「dsh web 输出的带 token 的完整地址」）填那行带 token 的地址 → 保存 | 列表第二行从 `A 模式` 变成 `A + B 模式` |
| 长按 →「验证 API 凭证」 | 弹「凭证有效」+ 下一步提示 |
| 长按 →「原生会话列表」 | 进入列表；顶部状态行显示「共 N 个会话（按最近活动排序）」 |
| 点「＋ 新建」 | 创建成功 → 自动进入新会话详情页 |
| 在详情页看投影 | 标题/工作目录/权限/预设/轮次统计/Token/上下文构成 都有值 |
| 看状态行 | 显示「水位 asOfSeq=N · 实时连接中 ★」 |
| 输入框发一条消息 | 立刻出现灰色「你 · 发送中…」气泡；随后变成正式消息 |
| 若模型不可用 | 出现红色「错误」条目（带错误码，例如 `NO_ADAPTER`） |
| 收到长回复时 | 消息**逐条追加**，不闪烁、滚动不跳（增量渲染） |
| 回复里有 ``` 代码块 | 等宽字体 + 浅底色 + 可横向滚动 |
| 「复制全文」 | 剪贴板得到分段的纯文本（【你】/【DSH】/【错误】/【工具】） |
| 按返回 → 回列表 | 列表自动刷新一次 |

❌ 常见问题：`HTTP 401`（token 过期，重启 DSH 后会变）、`创建失败`（看错误行）、列表空白（`session/list` 返回空）。

## 4. 诊断（故意制造故障）

| 做法 | 预期 |
|---|---|
| 把实例地址改成一个没开的端口（如 `:3999`）→ 测试连接 | `连不上` 或 502 类解释；错误页标题是**具体原因**而不是笼统的「连接不上」 |
| 停掉隧道（如果走公网域名） | `530` + 「cloudflared 没在跑」的解释 |
| 访问一个需要登录的地址 | `401` + 「这是正常现象，不是坏了」 |

## 5. WebView 行为（A 模式里点）

| 功能 | 怎么触发 | 预期 |
|---|---|---|
| JS 弹窗 | 官方 UI 里任何 confirm/alert | 弹原生对话框，点确定后页面继续 |
| 附件/文件选择 | 会话里点附件按钮 | 打开系统文件选择器，选中后能上传 |
| 下载 | 页面里点下载链接 | 通知栏出现下载，完成后可在系统下载里打开 |
| `target=_blank` 链接 | 点新窗口链接 | 同源在当前页打开；异源提示「已在浏览器打开」 |
| 麦克风/摄像头请求 | 页面请求权限时 | 明确提示「本版本不支持」，不卡住 |

## 6. 生命周期

| 步骤 | 预期 |
|---|---|
| 在会话详情里转屏 | 对话、输入框草稿、实时连接都保留 |
| 切到别的 App 停留 3 秒以上再回来 | 自动重拉历史并重连（断线期间的消息不会丢） |
| 连点返回退出 App 再进 | 有「继续上次：<实例名>」按钮 |

## 7. 多实例

| 步骤 | 预期 |
|---|---|
| 加两个**不同域名**的实例 | 互不影响 |
| 加两个**同域名不同端口**的实例，切换 | 弹「登录态可能串号」提示，可一键清除该域名 Cookie |

## 8. 极端情况（可选）

| 做法 | 预期 |
|---|---|
| 开发者选项 →「不保留活动」→ 切走再回来 | 不崩溃；页面重新加载 |
| 打开十几个 App 后再回来（触发渲染进程回收） | 显示「渲染进程被系统回收」并自动重建，**App 不退出** |

## 出问题时请给我这些

1. **哪一步**、**预期什么**、**实际什么**
2. 截图（界面问题最有用）
3. 如果是原生功能：详情页状态行（`asOfSeq` / 实时连接状态）、错误条目的完整文字
4. 如果是连接问题：长按实例 →「测试连接」的结果截图

## 已知限制（不用当 bug 报）

- 原生界面**只做 Markdown-lite**（代码块等宽渲染）；表格/嵌套列表/行内样式不处理 → 看排版好的内容请用官方界面
- 原生模式**不能传附件**（WebView 里可以）
- 原生界面不渲染系统消息与上下文注入（它们是几 KB 的提示词），只显示对话
- 断线后不会自动重连，需要手动刷新或切走再回来
- 多实例 Cookie 按域名共享（已做提醒，但没有真正隔离）
